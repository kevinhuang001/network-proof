# Android 实时二维码扫码

NetProof Air 只提供**实时连续扫码**。不再提供拍照或相册导入入口。扫描结果完全在离线设备上处理。

## 使用流程

1. 在桌面 Chrome 插件中打开待签名请求的二维码。
2. Android 手机上进入「扫描签名请求」，点击「开始连续扫码」，允许相机权限。
3. 后置相机对准屏幕，保持取景画面清楚、无反光；若为动态二维码，系统自动累计不同分片。
4. 进度达到 100% 且协议通过验证后进入签名审核页面。只有用户明确确认后才签名。
5. 点击停止或离开页面时关闭摄像头，不能在后台采集。

## 技术方案

- `src/lib/camera.ts` 请求 Android WebView 的相机权限，尽可能选择后置、高分辨率相机。
- `src/lib/liveQrScan.ts` 从视频流提取完整画幅，缩放至较大的解码分辨率，并以约 130ms 间隔使用 jsQR 解码。
- 解码后的片段进入 `@netproof/core` 的 `FrameCollector('NP-REQ')` 重组与去重，不完整帧不得进入签名阶段。
- `src/screens/Sign.tsx` 只处理扫描状态、进度、异常反馈和已完成请求。
- Android 不申请 `INTERNET` 权限，帧图像不持久化、不通过网络传输。
- 静态二维码可读；动态二维码需要连续扫描到足够片段才可恢复完整报文。

## 测试与验收

`pnpm verify`、Android 单元测试与模拟器测试只能证明构建和逻辑满足预期。**扫描成功率必须由真机验收**，至少使用一台 Android 手机及桌面 Chrome 扩展分别测试静态 NP-REQ、较长动态 NP-REQ、取消扫码、权限拒绝、旋转/不同亮度与签名响应。无法完成这些测试前，不能声称所有安卓机型必然扫得上。

如果无法扫描，先检查系统相机权限、后置镜头是否选中、摄像头分辨率与自动对焦、电脑屏幕反光、码是否完整显示在画面中。请记录机型、Android 版本、二维码类型、画面清晰度和分片进度，以便定位。
