# Android QR 扫描与故障排查

## 数据通路

插件在浏览器端生成离线签名请求（NP-REQ），Android 端读取二维码帧并用 `FrameCollector` 重建完整报文；用户核对金额、链和地址后，签名响应（NP-SIG）在 Android 屏幕显示，插件扫描取回结果。私钥和助记词始终保存在离线手机内，摄像头图像不得上传到网络。

### 扫描模式

- **连续扫码（推荐）**：`screens/Sign.tsx` 启动 `lib/liveQrScan.ts`，请求后置高分辨率摄像头，按约 130ms 的时间间隔对整个取景画面使用 jsQR 解码；成功分片进入同一个 `FrameCollector`，自动累计动态二维码片段。
- **拍照扫码**：Android 系统相机拍照，`photoScan.ts` 对原图分区解码，适合静态二维码或连续扫码不能对焦的机型。
- **相册导入**：不需要相机实时授权，但选择的图片只能贡献其包含的那一帧。
- **进度显示**：显示已恢复分片数与总数；不要将仅拍到一个动态帧当作完整请求。

## 为什么以前无法扫描

旧版仅提供单次拍照，每一次仅捕获动画的一帧，需要反复打开相机才能凑齐多个喷泉编码片段。动态二维码无法可靠地通过这一路径收集。连续扫码解决了传输方式与拍照模式不匹配的问题。

## 摄像头兼容性

`lib/camera.ts` 优先选择后置摄像头，尝试请求较高分辨率；`liveQrScan.ts` 按摄像头原始画面比例缩放到最长边不超过 1280 像素，避免取景框裁剪漏掉偏离中心的二维码。扫码结果间隔 1 秒去除重复静态帧；不同的动画片段不会被去重。离开扫描界面、取消启动或完成扫码均停止视频轨道。

Android Manifest 应保留 `CAMERA`、不申请 `INTERNET`。真机需授予系统相机权限，建议保持手机与电脑屏幕平行，避免反光、亮度过低和过远。

## 验证要求

1. 静态 NP-REQ 二维码可通过连续扫码、拍照和相册三条途径恢复。
2. 多帧 NP-REQ 动画可在连续扫码时累计，直到 `FrameCollector.complete`。
3. 离开页面或关闭连续扫码后，相机资源释放。
4. 解析非请求二维码不得进入签名流程。
5. 对主要 Android 版本与真实手机验证权限、前后置摄像头、自动对焦、亮度、横竖屏。
6. 运行 `pnpm verify`，在 Actions 执行 Android 原生测试，签名 APK 需验证没有 `INTERNET` 权限。

自动化测试不能完全替代实机扫描，发布前需要至少一台 Android 手机与桌面 Chrome 扩展进行完整离线签名回归。
