# NetProof 使用手册

## 1. 首次安装及备份

1. 在电脑上打开 [Releases](https://github.com/kevinhuang001/network-proof/releases)；核对 SHA256SUMS 后获取签名的 Android APK 与浏览器插件 ZIP。
2. 在目标 Android 手机上安装 APK，进入**飞行模式**，确认 Wi-Fi、蜂窝网络等已关闭。请勿在连网设备上导入真实助记词。
3. 创建钱包或导入现有助记词；按应用提示采集摄像头熵、设置设备密码并抄写助记词。助记词及可选 passphrase 均须离线保存；passphrase 变化会生成另一组地址，丢失无法找回。
4. 插件 ZIP 解压到稳定路径：打开 `chrome://extensions` → 启用开发者模式 →「加载已解压的扩展程序」→ 选取包含 `manifest.json` 的目录。更新时保留扩展的固定 ID（项目已保留 manifest 的 `key`）。
5. 使用新设备先做小额演练，确认签名和广播链路，再决定是否保管资产。

## 2. 配对与账户

- 手机选择「登录插件钱包」，显示公共账户的二维码；电脑伴侣点「添加钱包」并扫描。
- 扫码包含账户级 xpub 和设备导出的其他公开地址。电脑端可以导出 / 推导公开地址，不能签署交易。
- EVM 地址通常按 BIP44 路径 `m/44'/60'/0'/0/i` 派生；Solana 只显示已经由设备导出的硬化派生地址。
- 已存在的用户数据与存储键不应因升级而重命名或被清空。

## 3. 扫码签名

1. 在插件中查看交易网络、收款地址、金额、手续费和合约调用；仔细确认后进入请求二维码。
2. Android 点「扫描签名请求」→「拍照扫码」。拍到电脑屏幕上的**整张**二维码（含白边），避免反光和运动模糊。二维码应足够大，电脑端建议全屏 / 增亮。
3. 若相机未返回照片，先使用手机原生相机拍摄，再点「从相册选择二维码照片」，本机处理，不上传网络。
4. 对较大请求可能需要拍摄不同的动画帧；同一传输的分片会累计，直到完成或退出页面。
5. 手机离线校验请求并显示字段，用户再次逐项确认后签名；电脑扫描签名结果并验证请求关联及恢复地址，最终发送。

**不要对不认识的合约执行无限授权，不要仅凭扫码完成就跳过交易审核。**

## 4. Android 扫码故障排查

| 现象 | 处理 |
|---|---|
| 点击拍照无反应 | 确认系统相机可用、应用 CAMERA 权限允许；使用「从相册选择」作为替代 |
| 拍到照片，但读不出码 | 保证完整二维码（含白边）都在照片内；放大电脑端二维码、调整亮度、避免摩尔纹与反光 |
| 图片很大、QR 很小 | 新版本依次使用缩图、定位后的局部高清解码和重叠分区扫描 |
| 相册图片打不开 | 尽量选择系统相机拍摄的 JPEG/PNG；某些旧 WebView 不支持 HEIC |
| 一直显示分片不足 | 拍摄动画中**不同**帧，直到进度完成；不要重复拍同一帧 |
| Android 已签名但电脑读不出 | 检查电脑摄像头权限、是否扫描了签名结果而非旧请求，尝试稳健扫码速度 |
| 升级后提示签名不一致 | 不要卸载原应用；检查新 APK 是否由**与旧版本相同的证书**签名 |

在手机「设置 → 扫码自检」可以检查本机对模拟 JPEG 的解码通路，但自检通过**不能证明**真实镜头拍照成功，也不等于硬件已经验证。反馈错误时请提供 Android 版本、WebView 版本、照片分辨率及具体错误提示，不要发送助记词、私钥或含敏感交易内容的图片。

## 5. 更新与恢复

升级 APK 前备份助记词和 passphrase，并验证恢复流程。正常升级无需清除应用数据；不得通过卸载重装来尝试修复扫码问题。更换新手机时，请在离线状态重新导入助记词，确认派生路径和账户地址，再连接伴侣。

## 6. 关于发布位置

GitHub Releases 提供可下载安装包和校验值。Chrome Web Store 和 Google Play 商店需要各自的开发者账户与发布凭据，本项目的 GitHub Releases 发布工作流**不会**自动上架上述商店。
